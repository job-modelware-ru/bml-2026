# Влияние числа итераций на качество классификации SGDClassifier

Индивидуальное задание по курсу машинного обучения. Эксперимент выполнен на наборе данных MNIST с использованием `SGDClassifier` из scikit-learn.

## Цель работы

Исследовать, как количество итераций (эпох) обучения влияет на качество классификации и время работы модели `SGDClassifier`.

Задачи:

1. Изучить принцип работы `SGDClassifier`.
2. Подготовить набор данных MNIST для обучения и тестирования.
3. Обучить классификатор с различным числом эпох.
4. Сравнить качество моделей по нескольким метрикам.
5. Исследовать зависимость качества и времени обучения от числа эпох.
6. Выбрать подходящее число эпох и проверить модель на тестовой выборке.

## Математическое описание

`SGDClassifier` это линейный классификатор, который обучается методом стохастического градиентного спуска (SGD). В отличие от обычного градиентного спуска, на каждом шаге параметры обновляются по одному объекту, а не по всей обучающей выборке.

Функция, которую минимизирует модель:

$$J(\mathbf{w}) = \frac{1}{N}\sum_{i=1}^{N} L(y_i, f_{\mathbf{w}}(x_i)) + \alpha R(\mathbf{w})$$

где $L$ - функция потерь, $R$ - регуляризация, $\alpha$ задаёт её силу.

Правило обновления параметров на одном шаге:

$$\mathbf{w}_{t+1} = \mathbf{w}_t - \eta_t\left(\nabla L_i(\mathbf{w}_t) + \alpha\nabla R(\mathbf{w}_t)\right)$$

где $\eta_t$ - скорость обучения, а градиент вычисляется по текущему обучающему объекту.

В работе используется логистическая функция потерь (`loss="log_loss"`). Для бинарного случая она имеет вид:

$$L(y,p) = -\left(y\log p + (1-y)\log(1-p)\right)$$

где $p$ - предсказанная вероятность положительного класса. Для многоклассовой задачи `SGDClassifier` обучает набор бинарных классификаторов по схеме "один против всех".

Параметр `max_iter` задаёт число эпох. Параметр `tol=None` отключает остановку по сходимости, поэтому модель выполняет ровно заданное число эпох.

## Что было сделано

- Из MNIST случайно выбрана стратифицированная подвыборка из 8000 изображений, значения пикселей приведены к диапазону [0; 1].
- Данные разбиты на обучающую, валидационную и тестовую части в пропорции 70/15/15.
- Зафиксированы параметры: `loss="log_loss"`, `penalty="l2"`, `alpha=0.0001`, `learning_rate="optimal"`, `tol=None`.
- Исследуемый параметр: `max_iter` из набора 1, 2, 4, 8, 12, 16, 20. Для каждого значения модель обучена 3 раза с разными `random_state` (11, 22, 33), результаты усреднены.
- Метрики: Accuracy, Balanced Accuracy, Macro-F1, Log Loss и время обучения.
- Для вычисления вероятностей написана функция `safe_predict_proba`. При малом числе эпох все сигмоиды классов могут обнулиться, и стандартный `predict_proba` из sklearn даёт `NaN` (деление 0/0). В функции нормировка выполнена вручную, при нулевой сумме классы считаются равновероятными.
- Построены графики зависимости качества, Log Loss и времени обучения от числа эпох.
- Выбранная модель переобучена на train+val и проверена на тестовой выборке, для сравнения использован `DummyClassifier`.
- Построена матрица ошибок и показаны примеры неверно классифицированных изображений.

## Что получено

Средние значения на валидационной выборке:

| max_iter | Validation Accuracy | Время обучения, с |
|---|---|---|
| 1 | 0.815 | 0.20 |
| 2 | 0.840 | 0.39 |
| 4 | 0.847 | 0.71 |
| 8 | 0.846 | 1.41 |
| 12 | 0.842 | 2.08 |
| 16 | 0.847 | 3.26 |
| 20 | 0.851 | 4.21 |

Основные выводы:

1. **Качество.** Основной рост приходится на первые 2-4 эпохи. После 4 эпох качество колеблется в пределах 0.84-0.85, и эти изменения сопоставимы с разбросом между seed (std около 0.006-0.013), то есть значимого улучшения нет.
2. **Выбор числа эпох.** Формально лучший средний Validation Macro-F1 у 20 эпох (0.8497), но преимущество над 8 эпохами (0.8446) меньше разброса между запусками. Поэтому выбрано 8 эпох как компромисс: качество почти то же, а обучение примерно в 3 раза быстрее. Если важна калибровка вероятностей, стоит взять больше эпох (Validation Log Loss 1.32 при 8 эпохах и 0.94 при 20).
3. **Время.** Время обучения растёт примерно линейно (около 0.2 с на эпоху): от 0.20 с при 1 эпохе до 4.21 с при 20 эпохах. После 4 эпох дополнительное время почти не даёт прироста качества.
4. **Переобучение.** На обучающей выборке качество продолжает расти, разрыв между train и validation увеличивается с 4.7 до 8 п.п. Но Validation Log Loss продолжает снижаться, поэтому явного переобучения нет, скорее сказываются пределы линейной модели.
5. **Итог на тесте** (8 эпох, обучение на train+val):

| Модель | Accuracy | Balanced Accuracy | Macro-F1 | Log Loss |
|---|---|---|---|---|
| SGDClassifier | 0.884 | 0.883 | 0.882 | 1.081 |
| DummyClassifier | 0.113 | 0.100 | 0.020 | 2.301 |

6. **Ошибки.** Из 1200 тестовых объектов неверно классифицировано 139. Лучше всего распознаётся цифра 1 (128 из 135), хуже всего цифра 8 (85 из 117). Чаще всего путаются визуально похожие цифры: 9 и 4, 8 и 5, 9 и 7.
